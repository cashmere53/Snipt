# Implementation Plan

> 前提: プロジェクト雛形(Tauri / Vite / React / TS、モジュールの空実装、コンポジションルートと二段階 setup、ウィンドウ振り分けとプレースホルダ画面、Lint / Vitest / CI)は app-shell の tasks が用意する。本計画はそれを前提とし、雛形タスクを含まない。
> 並行の目安: 2(注釈モデル、純粋 TS)と 3(Rust 側)は 1 の完了後に並行して進められる。

- [x] 1. 基盤: 編集機能の依存と共有契約
- [x] 1.1 編集機能専用の依存とテスト実行環境を追加する
  - WebView 側に konva 10 系、react-konva 19.3 系、zustand 5 系を追加し、react-konva が要求する React 19.3 以上と整合していることを確認する
  - Rust 側に合成 PNG のデコード用クレートと、書き出しトークン生成用の UUID クレートを追加する
  - Vitest で Konva を Node 上で描画できるよう、編集機能のテストに限って DOM と canvas バックエンドを使う設定を加える
  - 完了状態: Konva の Stage を生成して 1 枚の canvas に描画するだけのスモークテストが `pnpm test` で通り、`cargo build` が成功する
  - _Depends: app-shell: プロジェクト雛形, Vitest 設定_
  - _Requirements: 1.1_

- [x] 1.2 (P) 編集画面を開く・閉じるための共有トレイトを定義する
  - 「既存なら前面化、無ければ生成し、呼び出し元をブロックしない」開く操作と、「開いていれば未保存注釈を flush してから閉じ、閉じ終わるか 3 秒経過までブロックする(メインスレッドから呼ばない)」閉じる操作の 2 つを持つ共有トレイトを、共有モジュールに追加する
  - キャプチャ ID は capture-library の共有型をそのまま使う
  - 完了状態: 共有モジュールからトレイトを参照する空実装を含めて `cargo check` が通り、screen-capture / capture-library がこのトレイトだけに依存してコンパイルできる
  - _Boundary: shared::EditorLauncher_
  - _Depends: capture-library: CaptureId_
  - _Requirements: 1.1, 1.4, 1.5, 11.2_

- [x] 1.3 (P) 編集画面用 IPC 契約の TypeScript 型を定義する
  - 6 つの command 名、セッション DTO、書き出し先 DTO、書き出し形式、エラー種別とエラー DTO、成功 / 失敗の結果型を、Rust 側と一対一になるよう共有 IPC 型として定義する
  - 外部クローズ要求イベントに加え、終了前フック用の「閉じずに flush する」要求と、その結果を Rust へ返す応答経路を同じ場所で定義する(design は名前を定めていないため、ここで名称と payload を確定し、capability にも反映する前提とする)
  - 完了状態: 型定義が `tsc --noEmit` を通り、エラー種別の列挙が design の 8 種と一致している
  - _Boundary: shared ipc (annotation-editor)_
  - _Requirements: 1.1, 10.4, 11.2_

- [x] 2. 注釈ドキュメントモデル(純粋 TS、Rust 側と並行可)
- [x] 2.1 注釈ドキュメントの型とスタイル設定を定義する

  - スタイル設定(色・線の太さ・文字サイズ・テキスト背景)の型、既定値、色パレット 8 色・太さ・文字サイズの選択肢と、不正値を既定値に置き換える検証を用意する
  - 完了状態: スタイル検証が不正な色・範囲外の数値・欠落フィールドを既定値へ戻すことを Vitest で確認できる

  - _Requirements: 2.6, 2.7, 5.6_

  - 完了状態: 各方向へのドラッグで 45 度スナップと正方形制約が期待値になり、範囲外・面積 0 の矩形が正しくクランプ / 無効化されることを Vitest で確認できる

- [x] 2.3 (P) 不可逆なモザイク計算を実装する

  - 完了状態: 出力の各ブロックが単一色かつ不透明で、元画素の値が出力に残らない入力例で検証する Vitest が通る

  - _Depends: 2.1_
  - _Requirements: 6.1, 6.3_

- [x] 2.4 (P) 図形操作とマーカー採番を実装する
  - 図形の追加・部分更新・複数削除・切り抜き設定 / 解除を、入力ドキュメントを変更しない純粋関数として実装する
  - マーカー番号は既存の最大番号 + 1(無ければ 1)とし、削除や更新で残りの番号を変えない
  - 完了状態: マーカー削除後も残りの番号が変わらず次の番号が最大 + 1 になること、切り抜き解除で元の範囲に戻ること、元ドキュメントが不変であることを Vitest で確認できる

  - _Requirements: 2.3, 2.4, 2.5, 7.2, 8.2, 8.3_

- [x] 2.5 (P) スナップショット方式の Undo / Redo 履歴を実装する
  - 過去・現在・未来のスナップショットを持ち、確定ごとに 1 件積み、新しい確定で未来を破棄し、上限 200 件を超えたら最古を捨てる
  - 同一ドキュメントの確定は履歴に積まない
  - 完了状態: 150 件の確定後に 100 回以上 Undo できること、Undo 後の確定で Redo 先が消えること、200 件超で最古が捨てられることを Vitest で確認できる
  - _Boundary: model (history)_
  - _Depends: 2.1_
  - _Requirements: 9.1, 9.2, 9.3_

- [x] 2.6 (P) 注釈ドキュメントの読み込み検証と版移行を実装する

  - 未知の新しい版や不正値は失敗理由付きで拒否し、呼び出し側が空ドキュメントで開けるようにする
  - 完了状態: 版 1 の往復、未知の版・不正色・重複 ID の拒否を Vitest で確認できる

  - _Depends: 2.1_
  - _Requirements: 1.1_

- [x] 2.7 (P) 保存封筒のエンコードを実装する

## Implementation Notes
- 1.2: capture-library 5.7 の削除で必要になったため、`shared::EditorLauncher` トレイト(`open_editor` / `close_editor`)を design どおりに先に追加した。実装と managed state への登録は 2 以降で行う(それまで capture-library は起動口が無いものとして動く)。
- 1.1: WebView 側は konva 10.9 / react-konva 19.3.2 / zustand 5.0 を追加した(react-konva 19.3 は React ^19.3.0 を要求し、既存の React 19.3.1 と整合)。Konva のテスト描画は devDependency の `canvas`(node-canvas 3 系、ビルド済みバイナリ)で行う。jsdom は `canvas` が入っていれば `<canvas>` をそれで描くため Vitest の設定変更は不要で、canvas を使うのは編集機能のテストだけ。pnpm 10 はインストールスクリプトを既定で止めるため、`pnpm-workspace.yaml` の `onlyBuiltDependencies` で `canvas` だけ許可した。Windows では canvas の最初の描画で fontconfig がシステムフォントをすべて走査し CI で 1 分以上かかったため、テストではフォントフォルダを持たない `src/test/fonts.conf` を `FONTCONFIG_FILE` で使う(文字は代替グリフで描かれる。文字の見た目を画素で確かめるテストが必要になったらフォントを同梱する)。それでも最初の 2D コンテキスト生成に Windows CI で数秒かかるため、描画するテストファイルは `beforeAll(warmUpCanvas, CANVAS_WARM_UP_TIMEOUT)`(`src/test/canvas.ts`)で先に初期化する。Rust 側の合成 PNG のデコードは capture-library で導入済みの `png` 0.18 を使い、追加したのは書き出しトークン用の `uuid`(v4)のみ。
- 1.3: `src/shared/ipc/annotation-editor.ts` に command 名(`EDITOR_COMMANDS`)・DTO・エラー種別 8 種・`IpcResult` を定義した。終了前フック用に、イベント `editor://flush-request`(payload `{ requestId }`、ウィンドウは閉じない)と、その応答 command `editor_flush_result`(`{ requestId, saved }`)を確定した。command は design の 6 つにこの応答を加えた 7 つになる(登録と capability は 6.x で行う)。外部クローズ要求 `editor://close-request` の payload は無し(`null`)。
- 2.1: 色パレットは design に色の指定が無いため、赤 `#E53935`(既定)・橙・黄・緑・青・紫・黒・白の 8 色にした。`validateStyle` は色は任意の `#RRGGBB` を受け付け、線の太さと文字サイズは選択肢に含まれる値だけを受け付ける(UI で選べる値と一致させるため)。
- 2.2: `snapAngle45` は終点をスナップ後の方向へ射影する(ポインタに最も近い点)。`toIntegerRect` は負の幅・高さも受け付ける。
- 2.3: `pixelate` は `ImageData` と同じ形の `Pixels`(`width` / `height` / `data`)を受け取り、新しい配列で返す。ブロックは左上基準で、右端・下端は部分ブロックになる。
- 2.4: 変化の無い操作(存在しない ID の更新・削除、同じ切り抜き)は同じドキュメントを返すので、履歴に積まれない。design の Testing Strategy にある「空テキストの確定」は `commitText` にした(空白だけの文字列も空とみなし、既存のテキストなら削除する)。
- 2.6: 未知のフィールドは読み込み時に捨てる。移行は `migrateDocument` に分け、版 1 が最初の版なので移行関数はまだ無い(段階的な適用と欠けた段の扱いはテスト用の移行関数で確認)。テキスト注釈の空文字と、切り抜き・モザイクの範囲外 / 非整数は不正として拒否する。
- 2.7: 封筒のエンコードは `services/save-envelope.ts`。JSON 長は UTF-8 のバイト数。
- 3.1: `EditorError` は `{ kind, message }` で直列化する(`message` は Display の日本語)。capture-library の `NotFound` は `notFound`、`Clipboard` は `clipboard`、それ以外は `library`(capture-library の表示文をそのまま使う)に変換する。種別の一覧が TS の `EDITOR_ERROR_KINDS` と同じであることをテストで照合する。
- 3.2: 版番号は整数(`u64` / `i64`)であることだけを確かめる。
- 3.3: 閉じ終わりの待機者は `std::sync::mpsc` の送信側で持つ(待つ側は 3.8 で `recv_timeout` を使う)。セッションは最初の利用時に作る。
- 3.4: 拡張子が `.jpg` / `.jpeg` 以外(例: `.bmp`)のときは、ファイル名はそのままで PNG として書く(design どおり、拡張子が無いときだけ `.png` を付ける)。書き込む前に、画像の先頭バイトが保存先の形式と一致するかを確かめる(一致しなければ `invalidPayload`)。一時ファイルは保存先と同じフォルダの `.<名前>.<uuid>.snipt-tmp`。
- 3.5 / 3.6: クリップボードと保存ダイアログは `ports::EditorDesktop` トレイト(`Arc<dyn EditorDesktop>` を managed state に置く)の背後に置き、テストは記録用の偽物を使う。本番実装 `SystemEditorDesktop` はダイアログを呼び出し元の編集ウィンドウを親にして開く。合成 PNG のデコードには `image`(capture-library で導入済み、`png` の上に載る)を使う。command は mock runtime の IPC 経由でテストする。command の登録と capability は 6.x で行う。
- 3.7: 初期サイズは画像を物理ピクセル 1:1 で表示する大きさ(論理サイズ = 画像 / 拡大率)に UI 余白 48×120 を足し、最小 800×600、上限は作業領域の 90%(作業領域が最小より小さいときは上限を優先)。タイトルは `Snipt - YYYY/MM/DD HH:MM:SS`、同じ秒の連番があれば ` (N)` を付ける。開く操作は `spawn_blocking` に渡してすぐ戻り、存在確認から生成までは 1 つの Mutex で直列化する。mock runtime はモニタ API が未実装のため、カーソル位置の作業領域は `WorkAreaAtCursor` として注入する。
- 3.8: 強制破棄した後は、破棄イベントが届かない場合(mock runtime やクラッシュした WebView)に備えてセッションも削除する。
- 3.9: 応答 command `editor_flush_result` は呼び出し元の編集画面が問われた要求にだけ答えられ、時間切れ後の遅い応答や他画面の要求 ID は警告ログだけで無視する。3 秒は全画面で共通の締め切り。待ち終えた要求は破棄するので、再試行では新しい要求 ID で問い直す。
- 3.10: `setup` は `Arc<EditorState>`・`Arc<dyn EditorDesktop>`(`SystemEditorDesktop`)・`Arc<dyn EditorLauncher>` を managed state に置き、終了前フック `annotation-editor` を登録する。
- 4.1: `localStorage` の読み書きは例外も含めて握りつぶし、読み込みは `validateStyle` で項目ごとに既定値へ置き換える。
- 4.2: `createEditorIpc(invoke)` で invoke を差し替えられるようにした(`mockIPC` はヘッダを渡さないため、書き出しトークンのヘッダは記録用の invoke で確かめる)。flush の応答 `editor_flush_result` も含めた 7 command を包む。編集 command 以外の失敗(ACL で拒否された等、`{ kind, message }` でない値)は `io` として扱う。
- 4.3: 復号は `createImageBitmap`(PNG の Blob から)。画素の展開は最初の `regionPixels` で一度だけ行い、`ImageData` を保持する。描画できるものなら何でも受け取れる(テストは node-canvas の canvas を使う)。
- 4.4: テキストの「選択色」背景の文字色は、輝度 0.4 を超える色(パレットでは黄と白)だけ黒、それ以外は白にした(黒の方がわずかに対比が高くなる 0.18 付近では赤・橙・緑・青の文字が黒になり、標識のような見た目にならないため)。マーカーの数字も同じ規則で色を決める。モザイクの写像は配置矩形だけを返し、ブロック画像と補間なしの描画は呼び出し側(レイヤー)が持つ。
- 4.5: ストアは `store/editor-store.ts` の `createEditorStore({ doc, style, viewport?, devicePixelRatio?, newId? })`(zustand/vanilla)。design の操作に、テキスト入力中の下書き更新 `updateTextDraft`、パン `setPan`、自動保存が使う `saveStarted` / `saveSucceeded(revision)` / `saveFailed(message)` を加えた。文書の変更(Undo / Redo を含む)は保存中でなければ保存状態を `dirty` にする。スタイルの各項目は持っている図形にだけ適用する(色: 矢印・四角・テキスト・マーカー、線の太さ: 矢印・四角、文字サイズと背景: テキスト)。新しいテキストの開始時に入力中のテキストがあれば先に確定する。切り抜きの確定・取消の後は選択ツールに戻し、画像全体と同じ範囲の確定は切り抜きなしとして扱う。Undo / Redo は入力中のテキストと切り抜き案を破棄する。描画ツールへの切り替えで選択を解除する。
- 4.6: 表示の計算は純粋関数として `store/view.ts` に分けた。`zoom` は画像 1px あたりの物理ピクセル、`pan` は Stage の位置(CSS px)。段階は 10, 25, 33, 50, 67, 75, 100, 125, 150, 200, 300, 400, 600, 800%。全体表示の倍率も 10% を下限にする。全体表示モードでは、ビューポート・DPR の変化と、表示対象(切り抜き中は画像全体、それ以外は切り抜き範囲または画像全体)の変化で再計算する。
- 4.7: `renderComposite(doc, source, format)` は上限超過を描画前に返し、描画は `drawComposite`(canvas を返す。テストはこちらで画素を確かめる)。モザイクは元画素から `pixelate` した画像を、補間を切ったレイヤーに整数座標で置き、他の図形より下に描く。エラーの表示文は `renderErrorMessage`。
- 4.8: `createAutosave({ store, compose, save, delayMs? })`。保存結果は design の `IpcResult` ではなく `{ ok: true } | { ok: false, message }` にした(合成の失敗は IPC エラーではないため。呼び出し側に必要なのは成否と表示文だけ)。保存中にタイマーが切れたら完了後に 1 秒後へ予約し直す。失敗後は次の変更か flush まで再試行しない。
- 5.1〜5.5 共通: 画面の部品は `store/editor-context.tsx` の `EditorContext`(ストア・元画像・ID 生成)から状態を読む。「画面上で確認」の完了条件は、jsdom + node-canvas 上で Konva にマウスイベントを送るテスト(`canvas/testing.tsx`)で代替し、実機での見た目は 7.1 で確かめる。
- 5.1: Stage はコンテナの大きさ(ResizeObserver)と DPR(`matchMedia` の resolution)を `setViewport` へ伝える。レイヤーは元画像 / モザイク(補間なし)/ 図形と選択ハンドル / 切り抜きマスクの 4 枚で、切り抜き指定中以外は `Group` の clip で切り抜き範囲に切り詰める。ホイールはパン(Shift で横)、Ctrl+ホイールはポインタ位置を基準に段階ズーム、中ボタンまたは Space+ドラッグでパンする。
- 5.2: 表示ノードは `ShapeView`(書き出しと同じ `shape-attrs` を使う)。モザイクの画像は書き出しと同じ `mosaicCanvas`(composite-renderer から公開)で作る。入力中のテキスト図形は表示しない(入力欄が代わりに表示する)。
- 5.3: ツールの判定は純粋関数 `canvas/tools.ts`(3px 未満のドラッグは何も作らない)。マーカーの直径は文字サイズの 4/3(24 → 32px)。画像(切り抜き後は切り抜き範囲)の外でのクリック・ドラッグ開始は無視する(切り抜きツールを除く)。ドラッグはステージ外に出ても window のイベントで続ける。テキスト入力中に描画ツールでクリックすると、そのクリックは入力の確定だけに使う。
- 5.4: 選択ツールのクリックで選択(Shift で追加 / 解除)、背景のクリックで選択解除。ドラッグ・変形の終了時に `moveShape` / `bakeScale` で 1 回だけ確定する。モザイクはドラッグ・変形中も rAF ごとに整数矩形へ丸めて画素を再計算する。テキストとマーカーは枠だけ表示して移動のみ。
- 5.5: ストアの `setTool("crop")` で切り抜き指定を始める(4.5 の変更)。切り抜きツールでのドラッグは新しい切り抜き案を作り、枠のドラッグとハンドルで調整する。Enter / Esc とツールバーの確定ボタンは 5.7 / 5.9 で結線する。
- 5.6: 入力欄は `EditorCanvas` のコンテナ内に絶対配置し、見た目(文字色・背景・余白・角丸)はキャンバスと同じ `textAttrs` から決める。伸長は `field-sizing: content`(WebView2 の Chromium が対応)と改行数の `rows`。入力欄のキー入力は伝播を止め、エディタのショートカットに渡さない。
- 5.7: ツールバーは文字のボタン(ツール名と、title にショートカット)。切り抜き指定中は「確定」「取消」、切り抜き済みなら「切り抜き解除」を出す。コピーと名前を付けて保存はコールバック(`onCopy` / `onSaveAs`)で、6.2 で結線する。
- 5.8: 通知バナーは `{ id, level, message }` の一覧と閉じるコールバックだけを受け取り、ストアには触れない。保存状態の文言は `saveStatusText`。
- 5.9: キーの判定は純粋関数 `shortcutFor`。ツールの文字キーと Ctrl+文字は `KeyboardEvent.code` で判定し、日本語入力モード(`key` が `Process`)でも物理キーで決まるようにした(ただし IME 変換中・入力欄では何もしない)。F5 / F3 / F7 / F12 と Ctrl+R / P / F / G / U / J / H / O / N / S は既定動作を止める。Ctrl+= は `+` と JIS 配列の `;` キーでも拡大する。
- 6.1: 読み込みは `services/load-editor.ts`(セッション → 元画像 → デコード → `parseDocument`)。注釈が読めない / 新しい版のときは元画像のみで開き、セッションの `warning` と合わせて通知バナーに出す。`EditorWindow` は IPC・ウィンドウ・デコード・ID 生成を `deps` で受け取り、テストでは差し替える(既定は Tauri)。ストアは `loadStyle()` で作り、`style` の変化を購読して `saveStyle` する。
- 6.2: `services/export-actions.ts` の `copyComposite` / `exportComposite` が失敗理由(文字列)か `null` を返し、`EditorWindow` が理由をエラーバナーに追加する。推奨名は `Snipt_<id>_export.png`(保存フォルダの `Snipt_<id>.png` / `_annotated.png` を上書きしない名前)。
- 6.3: `hooks/use-close-guard.ts`。ウィンドウ操作は `services/window-port.ts` の `WindowPort`(`onCloseRequested`、`editor://close-request` / `editor://flush-request` の購読、`destroy`)。どの経路でも先に `commitTextEdit` してから `flush` する。利用者のクローズ中に来た 2 回目のクローズは保存を繰り返さない。
- 6.4: `build.rs` と `lib.rs` の `generate_handler!` に 7 command を追加。`capabilities/editor.json` は `editor-*` に `core:default`・`core:window:allow-destroy`・本 spec の command のみを許可する(他の capability に `allow-editor-*` が無いことをテストで確認)。ラベル振り分けは app-shell の WindowRouter が既に `EditorWindow` を描画している。
