# Implementation Plan

> 前提: プロジェクトの土台(Tauri / Vite / React / TypeScript の構成、各機能モジュールのスタブ、コンポジションルートと 2 段階 setup、下流 `setup` のスタブ呼び出し、ウィンドウルーターとプレースホルダ画面、lint / テスト基盤、CI)は app-shell のタスクが用意する。本計画はそれらを作らず、依存として明記する。
>
> テスト方針: CI(windows-latest、実ディスプレイなし)では、純粋ロジック・状態機械・撮影後フローをフェイク(`CapturePlatform` / `OverlayPresenter` / 隣接サービスの偽物)で検証する。実画面を要する Windows アダプタのテストは `#[cfg(windows)]` かつ既定で無視(`#[ignore]`)とし、実機で手動実行する。

- [ ] 1. 基盤: Windows 依存の準備と実機での実現性確認
- [x] 1.1 Windows API 利用の準備とアダプタ置き場の宣言
  - Rust 側の依存設定に、設計で列挙した `windows` crate の機能(GDI、DWM、HiDpi、ウィンドウ管理、Direct3D11、DXGI、WGC、WinRT 相互運用、PrintWindow、ApiInformation)を Tauri が依存する版に揃えて追加する
  - 日時型(撮影日時)に必要な依存が capture-library と同じものになっていることを確認する
  - Windows アダプタ群(モニタ構成、凍結、ウィンドウ列挙、ウィンドウ撮影、背景ウィンドウ、構成変化監視、プラットフォーム統合)のモジュールを空の状態で宣言し、screen_capture モジュール内の各サブモジュールも宣言する
  - 完了時: Windows 向けのビルドと clippy(`-D warnings`)が CI で通り、追加したモジュールが空のまま組み込まれている
  - _Depends: app-shell: プロジェクト土台(Cargo 構成、`platform::windows` モジュール、`screen_capture` モジュールのスタブ)_
  - _Requirements: 4.1_

- [ ] 1.2 実機スパイク: 実現性リスクの計測とバックエンド方針の確定
  - 開発専用(配布物に含めない)の検証用プログラムで、4K + 1080p の 2 モニタ・100% + 150% の混在拡大率の実機を使い、次を計測・確認する: モニタごとの BitBlt 凍結時間、非表示から表示にした WebView2 オーバーレイの初回描画までの遅延、ネイティブ背景ウィンドウの表示時間
  - 透明 WebView の透明部分でクリックとポインタ移動を受け取れるか、ホットキー起点でオーバーレイへフォーカスが移り Esc を受け取れるかを確認する
  - Windows 10 1903/1909 相当の環境で、WGC のウィンドウ撮影時にオーバーレイのカーソルを非表示にすればカーソルが写らないか、Windows 11 で枠なし撮影の許可がどう振る舞うか、HDR モニタでの BitBlt の色を確認する
  - 結果に応じて方針を決める: 凍結が予算(80ms)を超えるなら `CapturePlatform` の背後に DXGI 実装を追加、初回描画が遅いならオーバーレイを透明のまま表示状態で待機させる方式、クリックが透過するならウィンドウモードでも背景を表示する方式。切り替えが必要な場合はそのタスクを本計画のグループ 5・6 の前に追記する
  - 完了時: 各計測値と判定(現行方式の継続 / 切り替え)が research.md の該当リスク項目に追記され、グループ 5・6 で採る方式が確定している
  - _Depends: app-shell: プロジェクト土台(`pnpm tauri dev` で起動できる Tauri アプリ)_
  - _Requirements: 1.2, 2.3, 4.4, 5.4_

- [x] 2. 純粋ロジック: 座標・モニタ構成・合成・当たり判定
- [x] 2.1 物理ピクセル座標と選択範囲のクランプ
  - 物理ピクセルの点と矩形、モニタローカル ⇔ グローバルの変換を実装する
  - ドラッグがモニタ端を越えたときに範囲をそのモニタの端で止めるクランプを実装する
  - 単体テスト: 端を越えたドラッグが端で止まる、負の座標を持つ左側・上側モニタでも正しく変換される、幅または高さ 0 の矩形を判定できる
  - 完了時: `cargo test` でクランプと変換のテストが CI 上で通る
  - _Requirements: 1.5, 1.7, 4.1, 4.2_

- [x] 2.2 モニタ構成モデルと構成指紋
  - モニタ情報(番号、デバイス名、物理矩形、DPI、拡大率、主モニタか)と、上・左の昇順に並べたモニタ構成を表す
  - デバイス名・物理矩形・DPI から構成指紋を算出し、点を含むモニタ(外れた場合は最寄りのモニタ)と仮想デスクトップの外接矩形を求める
  - 単体テスト: 拡大率だけが変わっても指紋が変わる、モニタ間の隙間にあるカーソルで最寄りモニタが選ばれる、負の座標を含む配置で外接矩形が正しい
  - 完了時: 構成指紋とカーソル下モニタ決定のテストが通る
  - _Requirements: 3.2, 4.2, 4.3_

- [x] 2.3 凍結フレームからの切り出しと全モニタ合成
  - モニタごとの凍結フレーム(BGRA、行ストライド付き)群と対象矩形(グローバル物理 px)から、非乗算 RGBA の撮影画像を作る合成を実装する。拡大縮小は一切行わない
  - モニタの無い領域は完全透明、モニタ領域は不透明にする
  - 拡大鏡用に、指定点を中心とする小さな画素片(半径 16 以下)を切り出す
  - 単体テスト: 100% と 150% のモニタを並べた配置で切り出し寸法が物理 px と一致する、全モニタ合成でモニタ外の画素が透明になる、ストライドに余白があるフレームでも正しく読む
  - 完了時: 範囲・全画面(1 枚)・全画面(全モニタ)のいずれも同じ合成で期待画素を返すテストが通る
  - _Requirements: 1.4, 3.3, 4.1, 4.2_

- [x] 2.4 (P) ウィンドウ候補の除外規則と当たり判定
  - ウィンドウ候補(識別子、物理矩形、タイトル、z 順)と、最前面から順に最初に点を含む候補を返す当たり判定を実装する
  - 最小化・非表示・クローク済み・矩形が空・Snipt 自身のオーバーレイと背景ウィンドウ・デスクトップやタスクバー系を候補から除く規則を、OS 非依存の判定として実装する
  - 単体テスト: 重なったウィンドウで最前面が選ばれる、除外対象が強調されない
  - 完了時: 当たり判定と除外規則のテストが通る
  - _Boundary: window_pick_
  - _Requirements: 2.1, 2.4_

- [x] 3. ポートと撮影後フロー
- [x] 3.1 エラー型・撮影セッション・2 つのポートとテスト用フェイク
  - 撮影エラー(構成変化、凍結失敗、ウィンドウ撮影失敗、オーバーレイ利用不可、古いセッション、内部エラー)と確定エラー(小さすぎる、強調中ウィンドウなし、古いセッション、構成変化)を定義する
  - 単調増加するセッション ID と、メモリ内のみで保持する撮影セッション(凍結フレーム、候補一覧、強調中候補、構成指紋、開始時刻、凍結時刻)を定義する
  - OS 撮影ポート(構成取得、カーソル位置、全モニタ凍結、ウィンドウ列挙、ウィンドウ撮影)と画面表示ポート(構築、範囲表示、ウィンドウ選択表示、強調、全非表示、自身のウィンドウ一覧)を定義する
  - テスト用に、呼び出しを記録し失敗を注入できるフェイク実装を両ポートについて用意する
  - 完了時: フェイクを使った最小のテストがコンパイル・実行でき、純粋モジュールが Tauri と `windows` crate を import していない
  - _Requirements: 1.1, 2.6, 4.3_

- [x] 3.2 (P) 撮影後フロー(コピー → 保存 → 編集)
  - 確定した画像をまずクリップボードへコピーし(PNG は渡さない)、失敗した場合は「クリップボードへのコピーに失敗しました」を通知して続行する
  - 画像(RGBA のまま、画素はコピーせず移す)と撮影情報(撮影方法、日時、ウィンドウキャプチャの場合のみタイトル)の保存を要求する
  - 保存に成功したらその ID、失敗した場合は保持された未保存アイテムの ID で編集画面を開くよう要求する。保存失敗の通知は capture-library に任せ、重ねて通知しない
  - 各段階の時刻を記録し、確定から編集要求までの経過をログに残す(1 秒超過は warn)。ウィンドウタイトルはログに出さない
  - テストのため、クリップボードと保存の呼び出し先を差し替えられる内部の受け口を設ける
  - 結合テスト(偽の保存先・偽の EditorLauncher・偽の Notifier): 呼び出し順が copy → save → open である、コピー失敗でも保存と編集要求が行われる、保存失敗時に未保存 ID で編集を開き二重通知しない
  - 完了時: 上記の結合テストが CI で通る
  - _Boundary: PostCaptureFlow_
  - _Depends: 2.3_
  - _Depends: capture-library: CaptureLibrary::save_capture, NewCapture, SaveCaptureError, clipboard::copy_image_
  - _Depends: annotation-editor: EditorLauncher_
  - _Depends: app-shell: Notifier_
  - _Requirements: 5.1, 5.2, 5.3, 5.4, 5.5_

- [x] 4. 撮影の状態機械(CaptureCoordinator)
- [x] 4.1 状態機械の骨格・撮影中フラグ・ワーカースレッド
  - Idle / Preparing / Selecting / Finalizing の状態と遷移を実装し、遷移はこのコンポーネントだけが行う
  - Idle 以外で届いた撮影要求を破棄してログのみ残す。撮影要求は即座に戻り、処理は専用ワーカースレッド(スレッド単位で PMv2、COM MTA 初期化済み)で行う
  - ワーカーでのパニックを捕捉して Idle に戻し、撮影中フラグが立ちっぱなしにならないようにする
  - app-shell の撮影要求トレイトを実装する
  - 単体テスト(フェイク): 撮影中の新規要求が無視される、パニック後に次の要求を受け付ける
  - 完了時: 状態機械のテストが通り、取消・失敗・完了のいずれでも Idle に戻ることが確認できる
  - _Depends: app-shell: CaptureRequester, CaptureMode_
  - _Requirements: 5.6_

- [x] 4.2 範囲モードの開始・拡大鏡・取消
  - 範囲キャプチャの要求で、構成を取得し、オーバーレイ構築時の指紋と異なれば再構築を依頼してから、自分のウィンドウを出す前に全モニタを凍結し、範囲表示を依頼して Selecting に進む
  - オーバーレイの描画完了通知を受けて、要求からの遅延をログに残す(200ms 超過は warn)
  - 拡大鏡の要求に、現在のセッションの凍結フレームから画素片を返す。セッション不一致は古いセッションとして拒否する
  - 取消要求でオーバーレイを隠し、凍結フレームを破棄して Idle に戻る。凍結失敗・表示失敗では「撮影を開始できませんでした」を通知して Idle に戻る
  - 単体テスト(フェイク): 取消でコピー・保存が呼ばれない、凍結失敗で通知され Idle に戻る、古いセッション ID の操作が無視される
  - 完了時: フェイク上で「要求 → 凍結 → 範囲表示 → Selecting」と「取消 → Idle」がテストで確認できる
  - _Depends: app-shell: Notifier_
  - _Requirements: 1.1, 1.2, 1.3, 1.6_

- [x] 4.3 範囲の確定
  - 確定要求の範囲を対象モニタで再クランプし、幅または高さが 1 未満なら状態を変えずに小さすぎるエラーを返す
  - 構成を取り直して指紋が変わっていれば撮影を取り消す
  - 有効な確定ではオーバーレイを隠し、合成で切り出して Finalizing に進み、撮影後フローを実行してから Idle に戻る(撮影日時は凍結時刻)
  - 単体テスト(フェイク): 小さすぎる確定で Selecting のまま、指紋不一致で取消、有効な確定で撮影後フローに正しい寸法の画像が渡る
  - 完了時: 範囲キャプチャの確定経路がフェイク上で端から端まで通る
  - _Depends: 3.2_
  - _Requirements: 1.4, 1.5, 1.7, 4.3_

- [x] 4.4 ウィンドウモード
  - ウィンドウキャプチャの要求で、自身のオーバーレイと背景ウィンドウを除外した候補一覧をスナップショットとして取得し、ウィンドウ選択表示を依頼する
  - ポインタ移動ごとに当たり判定し、強調矩形を表示側へ送る
  - 確定要求で強調中ウィンドウを 1 秒のタイムアウトで撮影し、成功したらタイトル付きで撮影後フローを実行する(撮影日時は撮影時刻)。強調中ウィンドウが無ければエラーを返す
  - 撮影に失敗したら「ウィンドウを撮影できませんでした」を通知し、何も保存・コピーせずに Idle に戻る。取消は範囲モードと同じく何もしない
  - 単体テスト(フェイク): 失敗時に通知のみでコピー・保存が呼ばれない、除外一覧に自身のウィンドウが渡される、ポインタ移動で強調が更新される
  - 完了時: ウィンドウモードの確定・失敗・取消がフェイク上のテストで確認できる
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.5, 2.6_

- [x] 4.5 全画面モード
  - 全画面キャプチャの要求で選択画面を出さずに凍結し、設定の全画面対象を読み、カーソル下モニタ 1 枚または全モニタを実際の配置どおりに合成して撮影後フローを実行する
  - テストのため、設定の読み取り先を差し替えられるようにする
  - 結合テスト(フェイク): 対象設定によって結果の寸法が変わる、オーバーレイの表示が一度も依頼されない、全モニタの空き領域が透明になる
  - 完了時: 全画面の 2 つの対象についてテストが通る
  - _Depends: app-shell: SettingsStore::get, Settings.fullscreen_target_
  - _Requirements: 3.1, 3.2, 3.3_

- [x] 4.6 モニタ構成変化への対応
  - 構成変化の通知を受けたとき、Preparing / Selecting なら通知なしで撮影を取り消す
  - どの状態でもオーバーレイを「要再構築」とし、Idle になってから 500ms のデバウンス後に再構築を依頼する
  - 単体テスト(フェイク): 選択中の構成変化で取消される、連続した変化で再構築が 1 回にまとまる、次回の撮影で新しい構成が使われる
  - 完了時: 構成変化の取消と再構築予約がテストで確認できる
  - _Requirements: 4.3_

- [ ] 5. Windows アダプタ(実機依存。CI ではビルドのみ、実画面テストは既定で無視)
- [ ] 5.1 (P) モニタ構成の取得と DPI 認識の検証

  - 実機テスト(既定で無視): 100% + 150% の構成で物理矩形と拡大率が正しく得られる

  - 実機テスト(既定で無視): 既知の画素パターンを表示した 150% モニタで、凍結画像が物理 px で 1 対 1 に一致し、カーソルが写らない

  - 矩形は見えないリサイズ枠を含まない拡張フレーム境界、タイトルはウィンドウテキストから取る
  - 実機テスト(既定で無視): 最小化したウィンドウと別仮想デスクトップのウィンドウが一覧に出ない

- [ ] 5.4 (P) WGC による単体ウィンドウ撮影
  - D3D11 デバイスを初回利用時に作って保持し、ウィンドウから撮影アイテムを作って 1 フレームだけ取得する。内容サイズで切り詰めて読み出し、非乗算 RGBA にする
  - 対応する OS ではカーソル撮影を無効にし、Windows 11 で許可された場合は黄色枠を無効にする(起動時に枠なしアクセスを要求し、可否をログに出す)
  - 最初のフレームをタイムアウトまで待ち、デバイス消失時は再生成して 1 回だけ再試行する
  - 実機テスト(既定で無視): 半分隠れたウィンドウを撮ってそのウィンドウ自身の内容が得られる
  - 完了時: 実機テストで隠れた部分を含むウィンドウ画像が物理 px で得られる

- [ ] 5.5 PrintWindow フォールバックと撮影失敗の判定

  - 両方失敗したらウィンドウ撮影失敗のエラーを返す
  - 実機テスト(既定で無視): WGC を強制的に失敗させたとき PrintWindow で撮れる、応答しないウィンドウでタイムアウトして失敗が返る
  - 完了時: フォールバックとタイムアウトの経路が実機で確認できる

  - 実機テスト(既定で無視): 背景ウィンドウ表示後の画面が凍結時の画面と画素一致し、表示に 15ms 程度で済む
  - 完了時: 実機で背景ウィンドウの表示・非表示ができ、凍結画像がずれなく表示される

## Implementation Notes
- 1.1: `windows` crate(0.62、Tauri の依存と同じ 1 版のみ)に設計の features と、D3D11 デバイス作成に要る `Win32_Graphics_Direct3D` / `Win32_Graphics_Dxgi_Common` を追加。日時は capture-library と同じ `chrono` 0.4 を使う。`platform::windows` の 7 アダプタと `screen_capture` の各サブモジュールは doc コメントだけの空モジュールとして宣言した。
- 2.1: 矩形は右端・下端を含まない(`x..x + width`)。辺の計算は `i64` で行い、`i32` / `u32` の範囲に収める。ドラッグのクランプは `clamp_point`(端を含む)または `clamp_to_monitor`(モニタ外の矩形は最寄りの端で空になる)。
- 2.2: ローカル ⇔ グローバルの変換は、設計の `geometry::to_global(&MonitorInfo, ..)` ではなく `MonitorInfo::to_global` / `to_local` / `point_to_local` に置いた(geometry → topology の依存方向を保つため)。`MonitorTopology::new` が上・左の昇順に並べて `index` を振り直す。指紋はプロセス内で比較するだけなので `DefaultHasher`。
- 2.3: 拡大鏡の画素片 `patch` は `compose_region` の特別な場合(半径は `MAX_PATCH_RADIUS` = 16 に丸める)。行が足りない凍結フレームは panic せず、その部分を透明にする。
- 2.4: OS から読んだ状態を `TopLevelWindow` で受け取り、`candidates` が除外規則(非表示・最小化・クローク・空矩形・Snipt 自身・`Progman` / `WorkerW` / `Shell_TrayWnd` / `Shell_SecondaryTrayWnd`)を適用して z を最前面から 0 で振る。
- 3.1: `CaptureError::GrabFailed` は設計の `source: windows::core::Error` ではなく `reason: String` を持つ(純粋側を `windows` crate から切り離し、Linux でもビルドできるようにするため)。`CommitError` は `{ "kind": "tooSmall" }` 形式で直列化する。フェイクは `ports::fake` の `FakePlatform` / `FakePresenter`(呼び出しを文字列で記録し、`grab_error` / `fail_show` などで失敗を注入)。
- 3.2: 差し替え口は `CaptureClipboard`(本番は `SystemClipboard`)と `CaptureStore`(`CaptureLibrary` が実装)。確定時刻は `CaptureOutcome::committed_at` で受け取り、コピー・保存・編集要求の経過を 1 行でログに出す(1 秒超過は warn、ウィンドウタイトルは出さない)。コピー失敗の通知は Warning レベル。
- 4.1: ワーカーは `worker::CaptureWorker`(`run` / `run_after`)で差し替える。本番は `ThreadWorker::spawn(init)` が `capture-worker` スレッドを 1 本立て、`init`(スレッド DPI・COM 初期化、5.x で渡す)を先に実行する。テストは呼び出し元で即実行する `InlineWorker`(`holding()` で保留も可)。ジョブは `catch_unwind` で包み、パニックでは自セッションなら Idle に戻してオーバーレイを隠し「撮影に失敗しました」を通知する。依存は `CoordinatorPorts` にまとめ、撮影後フローは `PostCaptureSink`(`PostCaptureFlow` が実装)で受ける。
- 4.2: 拡大鏡の範囲外(モニタ外の点・不明なモニタ・ウィンドウモード)は `CaptureError::OutOfRange`。描画完了の遅延ログはモニタごとに出す。表示中に取消された場合は表示後に隠し直す。
- 4.3: 不明なモニタ番号での確定は `StaleSession`。構成が読めないときも指紋不一致として取り消す。
- 4.4: 表示直後にカーソル位置で一度当たり判定し、最初の強調を送る。ウィンドウ撮影はオーバーレイを出したまま行い、終わってから隠す。空のタイトルは `None` で渡す。
- 4.5: 全画面対象は `FullscreenTargetSource`(`Fn() -> FullscreenTarget`)で毎回読む。確定時刻は要求時刻とする。
- 4.6: 再構築の予約は世代番号で間引き、最後の変化の 500ms 後の 1 回だけが実行される。撮影開始時の `ensure_overlays` が再構築した場合は予約済みの再構築は何もしない。
