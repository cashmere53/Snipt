# Implementation Plan

> 前提: プロジェクト雛形(Tauri / Vite / React / TS、モジュールのスタブ、合成ルートと 2 段階 setup、spec 別区画、WindowRouter とプレースホルダー、lint / test、CI)は app-shell のタスクが用意する。本計画は雛形を作らず、それに依存する。
> 下流(screen-capture / annotation-editor)が早く着手できるよう、共有契約(CaptureId、共有型、イベント、copy_image、CaptureLibrary の保存・元画像取得)を前半に置く。

- [x] 1. 共有契約と依存の準備
- [x] 1.1 本 spec の依存クレートと Tauri 設定を追加する
  - PNG エンコード・画像縮小・フォルダ監視・ごみ箱・エクスプローラー表示・Windows API・日時・エラー型の各依存を、Cargo 定義の capture-library 区画に追加する
  - Tauri の asset プロトコル機能を有効化し、設定でスコープ空のまま有効にし、CSP の画像読み込み元に asset を許可する
  - 合成ルートのプラグイン区画で opener プラグインを登録する
  - 完了時: 依存追加後のワークスペースが Windows でビルドでき、既存の lint / テストが通る
  - _Depends: app-shell: プロジェクト雛形, 合成ルートのプラグイン区画_
  - _Requirements: 3.6, 3.8_

- [x] 1.2 キャプチャ ID の共有型を作る
  - 撮影日時(ローカル時刻)由来の `YYYYMMDD_HHMMSS` と同秒衝突時の `_NN`(02〜99)の形式だけを受け付ける検証付きの型にする
  - 文字種を数字とアンダースコアに限り、辞書順が撮影順と一致するようにする。文字列として透過的にシリアライズする
  - `..\` や区切り文字・空文字・桁数違いを拒否する単体テストを書く
  - 完了時: 共有モジュールから ID 型を参照でき、検証・順序・シリアライズの単体テストが通る(下流 spec が参照開始できる)
  - _Depends: app-shell: プロジェクト雛形(共有モジュール)_
  - _Requirements: 1.2_

- [x] 1.3 保管庫の共有データ型とエラー型を定義する
  - 履歴項目(ID・撮影日時・撮影方法・物理ピクセルの幅高さ・ウィンドウタイトル・元画像 / 合成済み画像 / サムネイルのパス・注釈有無・サムネイル版)と、表示元パス(合成済みがあればそれ、無ければ元画像)を返す規則を定義する
  - 新規キャプチャ入力(RGBA または PNG の画像、撮影方法、撮影日時、ウィンドウタイトル)、編集用セッション(注釈・警告・未保存フラグ)、保管庫エラー(種別タグ付き)、保存失敗エラー(理由と未保存項目)、削除結果を定義する
  - WebView 向けに camelCase、撮影日時を RFC 3339、エラーを `kind` タグ付きでシリアライズする
  - 完了時: シリアライズ形の単体テスト(撮影方法の表記、ウィンドウタイトルの null、エラーの kind)と表示元パス規則のテストが通る
  - _Depends: app-shell: CaptureMode_
  - _Requirements: 1.3, 1.4, 1.6, 3.2, 3.5, 3.6_

- [x] 1.4 保管庫イベントの名前・payload・発行ヘルパーを作る
  - 追加・更新・除去(理由: 削除 / ディスク上で欠落)・再読み込み(保存先)の 4 イベントを全ウィンドウへ発行するヘルパーにする
  - 完了時: 各イベントの payload が設計どおりの JSON 形になることを単体テストで確認できる
  - _Requirements: 3.3, 3.7, 4.2, 5.2_

- [x] 1.5 WebView 側の IPC 型と command ラッパーを作る
  - Rust の共有型と一対一の TS 型(ブランド付き ID、履歴項目、エラー種別、除去理由、イベント表)を定義する
  - 一覧・編集画面で開く・コピー・エクスプローラー表示・削除・欠落除去の各ラッパー、型付きイベント購読、サムネイル URL(asset 変換 + 版クエリ)を用意する
  - 完了時: TS strict で型検査が通り、サムネイル URL 生成(未生成時 null、版クエリ付与)の Vitest が通る
  - _Depends: app-shell: TS 共有型 CaptureMode_
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 3.5, 3.6, 3.7, 4.2, 5.2_

- [x] 2. OS アダプタ(他 spec と共有)
- [x] 2.1 (P) 画像クリップボードアダプタを作る
  - 1 回のクリップボード操作内で、アルファ付き CF_DIBV5(ボトムアップ)と登録形式 "PNG" の両方を設定する。PNG が渡されないときは高速圧縮で作る
  - 他プロセスが使用中のときは短い間隔で最大 10 回再試行し、駄目なら「使用中」エラーを返す。呼び出しスレッドを選ばない
  - RGBA から DIBV5 ヘッダと画素列への変換を純粋関数に分け、単体テストする
  - 完了時: 変換の単体テストが通り、Windows 上でコピーした透過画像をペイントとチャットアプリに貼り付けられる(screen-capture / annotation-editor が利用開始できる)
  - _Boundary: platform clipboard_
  - _Depends: app-shell: プロジェクト雛形(platform モジュール)_
  - _Requirements: 3.5_

- [x] 2.2 (P) シェル操作アダプタを作る
  - 複数パスをまとめてごみ箱へ移動する、ファイルを選択した状態でエクスプローラーを開く、フォルダに隠し属性を付ける、の 3 操作を用意する
  - 完了時: Windows 上の一時フォルダで、ごみ箱移動後に元パスが消えて復元でき、隠し属性が付き、表示操作でエクスプローラーが該当ファイルを選択して開く
  - _Boundary: platform shell_
  - _Depends: 1.1_
  - _Requirements: 1.5, 3.6, 4.2_

- [x] 2.3 デスクトップ操作の差し替え口を作る
  - ごみ箱・表示・クリップボードの 3 操作をまとめた差し替え可能な口と、2.1 / 2.2 を呼ぶ本番実装を用意し、失敗を保管庫エラー(shell / clipboard 種別)に写像する
  - 呼び出しを記録するテスト用の偽実装を用意する
  - 完了時: 偽実装で呼び出し内容を検証するテストが書け、本番実装がビルドされる
  - _Depends: 2.1, 2.2_
  - _Requirements: 3.5, 3.6, 4.2_

- [x] 3. 保存形式(純粋モジュール)
- [x] 3.1 (P) ファイル名と ID の採番を作る
  - 撮影日時から `Snipt_YYYYMMDD_HHMMSS` を作り、存在確認関数で衝突したら `_02`〜`_99` を順に試す
  - 完了時: 同じ秒の 3 件が `_02`、`_03` になり、生成順と辞書順が一致する単体テストが通る
  - _Boundary: Naming_
  - _Requirements: 1.2_

- [x] 3.2 (P) 保存先フォルダの配置規則を作る
  - ルートから元画像・合成済み画像・注釈・サムネイル・索引・一時フォルダの各パスを導出する
  - ルートと管理用隠しフォルダ一式が無ければ作成し、管理用フォルダに隠し属性を付ける
  - 完了時: 一時ディレクトリで、存在しない保存先に対してフォルダ一式が作られ、パス導出の単体テストが通る
  - _Boundary: LibraryLayout_
  - _Depends: 2.2_
  - _Requirements: 1.5, 2.3_

- [x] 3.3 (P) メタデータ付き PNG の書き込みと読み取りを作る
  - RGBA 入力は高速圧縮でエンコードし、PNG 入力はメタを付け直す。撮影 ID・日時・撮影方法・ウィンドウタイトルを iTXt に埋め込む
  - 先頭チャンクだけを読んで幅・高さとメタを取り出す。未知フィールドは無視する
  - 画素数 0・バイト長不一致・壊れた PNG を入力不正として拒否する
  - 完了時: 日本語ウィンドウタイトルを含むメタの往復、IHDR からのサイズ取得、入力不正の拒否の単体テストが通る
  - _Boundary: PngMeta_
  - _Requirements: 1.1, 1.3, 1.4_

- [x] 3.4 (P) 原子的なファイル置き換えを作る
  - 一時フォルダに書いて flush してから同一ボリューム内で置き換える
  - 容量不足・アクセス拒否を、理由を示す保管庫エラー(容量不足 / 権限なし)に写像する
  - 完了時: 置き換え後に内容が新しくなり、読み取り専用フォルダでは権限なしエラーが返る単体テストが通る
  - _Boundary: AtomicFs_
  - _Requirements: 1.6, 2.2_

- [x] 4. 索引・サムネイル・未保存保持
- [x] 4.1 メモリ索引と索引ファイル形式を作る
  - 現在のルートの全項目をメモリに持ち、撮影日時の降順(同値は ID 降順)で返す。追加・更新・除去・取得を提供する
  - 版付き索引ファイルへのスナップショットを作り、パスはルート相対の基底名から導出する
  - 完了時: 並び順・更新・除去と索引ファイルの往復の単体テストが通る
  - _Requirements: 1.1, 3.1, 3.8_

- [x] 4.2 索引の読み込み・突き合わせ・再構築を作る
  - 索引ファイルを読み、ルートと注釈フォルダのファイル名一覧と突き合わせる。索引に無いメタ付き元画像を取り込み、元画像が無い項目を除き、合成済み画像と注釈の有無を補正する
  - 索引ファイルが無い・破損・未知の版のときはファイルから再構築して書き直す。再構築時間と突き合わせ件数をログに出す
  - 完了時: 索引に無い PNG の取り込み、欠落項目の除外、破損 / 未知版での再構築、旧フォルダに戻したときの履歴復元の単体テストが通る
  - _Requirements: 3.7, 5.2_

- [x] 4.3 (P) サムネイル生成ワーカーを作る
  - 保存直後はメモリ上の画像から、それ以外は表示元パスの画像から、長辺 320px・アスペクト維持・透明保持の PNG を作る
  - 同じ ID の要求を合流し、新しい順に処理して先頭の表示分を優先する。完了ごとに通知コールバックを呼ぶ。上書き生成で冪等にする
  - 完了時: 縦長 / 横長 / 透過画像の縮小結果と、重複要求が 1 回の生成になることの単体テストが通る
  - _Boundary: ThumbnailWorker_
  - _Requirements: 3.2, 3.8_

- [x] 4.4 (P) 未保存キャプチャの保持を作る
  - 保存に失敗したキャプチャの項目・PNG バイト・失敗理由を ID ごとにメモリに保持し、取得・列挙・除去を提供する。一覧には出さない
  - 完了時: 保持・取得・除去の単体テストが通る
  - _Boundary: UnsavedStore_
  - _Requirements: 1.6_

- [x] 5. CaptureLibrary サービス(下流 spec が使う入口)
- [x] 5.1 サービスの状態と setup を作り、合成ルートに接続する
  - 書き込みロック付きの状態(現在ルート・索引・編集中セッション表・削除済み集合)と未保存保持を持つサービスを作る
  - setup で設定ストアから保存先を取得し、索引読み込みをバックグラウンドで始め、完了まで一覧取得を待たせる。サムネイルフォルダだけを asset スコープに許可する
  - サービスを managed state に登録し、合成ルートの capture-library 区画のスタブを本物の setup 呼び出しに置き換える
  - 完了時: アプリ起動時に setup が成功し、下流 spec が managed state からサービスを取得でき、既存フォルダの一覧が新しい順で得られる
  - _Depends: 4.2, 4.3, 4.4_
  - _Depends: app-shell: SettingsStore, 合成ルート(2 段階 setup の capture-library 区画)_
  - _Requirements: 3.1, 3.8, 5.1_

- [x] 5.2 撮影結果の保存(成功経路)を作る
  - 書き込みロック下で、メモリ上の PNG エンコード → フォルダ作成 → 採番 → 原子的書き込み → 索引登録 → 追加イベント の順に行い、項目を返す
  - サムネイル生成は戻り値の後に行い、完了時に更新イベントを出す。索引ファイルの書き出しは 500ms 以内に合流させ、失敗しても保存失敗にしない。保存時間をログに出す
  - 完了時: 一時ディレクトリへの保存で元 PNG・索引登録・追加イベントがそろい、存在しない保存先でもフォルダが作られる結合テストが通る(screen-capture が保存を呼べる)
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5, 3.3_

- [x] 5.3 撮影結果の保存(失敗経路)を作る
  - 書き込み失敗時に PNG を未保存保持に入れ(書ければ一時フォルダにも書く)、理由付きで通知し、未保存項目を含む保存失敗エラーを返す
  - 入力不正は呼び出し側の不具合として開発時アサートし、入力不正を理由に通知する
  - 完了時: 読み取り専用フォルダへの保存で、通知が 1 回出て、保存失敗エラーの未保存 ID が保持されている結合テストが通る
  - _Depends: app-shell: Notifier_
  - _Requirements: 1.6_

- [x] 5.4 再編集用の読み込みと元画像バイトの提供を作る
  - 項目と注釈(あれば)をそろえた編集セッションを返し、編集中セッション表に登録する。注釈ファイルが無ければ注釈なし、読めない / JSON でない / 版が整数でなければ注釈なし + 読み込み失敗の警告にする
  - 未保存項目は未保存フラグと未保存の旨の警告を付け、元画像バイトは未保存保持から返す。通常項目はディスクから返す
  - 完了時: 注釈あり・なし・破損・未保存の各ケースで期待どおりのセッションと元画像バイトが返る結合テストが通る(annotation-editor が読み込みを呼べる)
  - _Requirements: 1.6, 2.4, 2.6_

- [x] 5.5 注釈と合成済み画像の保存を作る
  - 注釈がオブジェクトで版が 1 以上の整数か、合成済み画像が PNG として読めるかを検証する
  - 未保存項目なら先に元画像の保存を再試行し、成功すれば通常項目にして追加イベントを出し、失敗すればエラーを返す
  - 注釈 JSON と合成済み PNG を原子的に置き換え、注釈ありにしてサムネイルを再生成し、更新イベントを出す。元画像は変更しない。削除済み ID は見つからないエラーにしてファイルを作らない。保存先切り替え後も編集中セッションは元の場所に書く
  - 完了時: 注釈保存後に元 PNG のバイト列が不変で、合成済み PNG が置き換わり、不正な版が拒否される結合テストが通る
  - _Requirements: 1.6, 2.1, 2.2, 2.3, 2.5_

- [x] 5.6 コピー・エクスプローラー表示・欠落除去を作る
  - コピーは表示元パスの PNG を読んでデコードし、RGBA と元の PNG バイトをクリップボード口に渡す
  - 表示は表示元パスを選択状態で開く。欠落除去は元画像が実在しない ID だけを索引から除き、ディスク上で欠落の理由で除去イベントを出す(エラーにしない)
  - 完了時: 偽のデスクトップ操作で、合成済みがある項目は合成済み画像が、無い項目は元画像が渡り、欠落除去が実在項目を残す結合テストが通る
  - _Depends: 2.3_
  - _Requirements: 3.5, 3.6, 3.7_

- [x] 5.7 編集画面で開く操作と削除を作る
  - 編集画面で開く操作は、編集画面起動口を呼び出し時に遅延解決して依頼する
  - 削除は、ロックを取る前に対象ごとに編集画面のクローズ(未保存注釈の flush 込み)を依頼し、その後ロック下で削除済みに登録し、元画像・合成済み画像・注釈をまとめてごみ箱へ移し、サムネイルを消し、索引から除いて削除理由の除去イベントを出す。未保存保持からも除く。起動口が未登録ならクローズを省く
  - 一部の失敗は成功分だけ除き、失敗分を結果に含める
  - 完了時: 偽の起動口と偽のデスクトップ操作で、クローズがロック外で先に呼ばれ、3 ファイルがごみ箱に渡り、一覧から消える結合テストが通る
  - _Depends: 2.3_
  - _Depends: annotation-editor: EditorLauncher トレイト定義(open_editor / close_editor)_
  - _Requirements: 3.4, 4.2, 4.3_

- [x] 5.8 終了前フックを登録する
  - setup で終了前フックに登録し、未保存保持の各項目を現在の保存先へ再保存する(冪等)。成功分は通常項目にして追加イベントを出す
  - 再保存できずに残った項目を「撮影画像: <ID>」として終了確認に返す
  - 完了時: 書けない保存先では残り項目が返り、書ける保存先に変えて再実行すると空になる結合テストが通る
  - _Depends: app-shell: BeforeExitHooks_
  - _Requirements: 1.6_

- [x] 6. 保存先切り替えと外部変更の検知
- [x] 6.1 保存先フォルダの監視を作る
  - ルートだけを非再帰で監視し、300ms でデバウンスし、Snipt の名前パターンだけを扱う
  - 索引にある元画像の削除・リネームは欠落除去に回し、合成済み画像の消失は合成済みなしにしてサムネイルを元画像から作り直し、更新イベントを出す。自アプリの削除によるイベントは無視する
  - 完了時: 一時ディレクトリで外部から元 PNG を消すと除去イベントが、合成済み PNG を消すと更新イベントが出る結合テストが通る
  - _Requirements: 3.7_

- [x] 6.2 保存先の切り替えを作る
  - 設定の変更通知で保存先が変わったら、監視停止 → 新ルートの索引読み込み → asset スコープを新しいサムネイルフォルダに付け替え(旧スコープを外す)→ 監視再開 → 再読み込みイベント、の順で行う。既存ファイルは移動しない
  - 切り替え中の保存は書き込みロックで待たせ、新ルートに保存する。setup で監視を開始する
  - 完了時: 保存先を変えると一覧が新フォルダの内容になり、以降の保存が新フォルダに入り、旧フォルダに戻すと旧履歴が戻る結合テストが通る
  - _Depends: app-shell: SettingsStore(変更購読)_
  - _Requirements: 5.1, 5.2_

- [ ] 7. 履歴画面向けの command を作る
  - 一覧・編集画面で開く・コピー・表示・削除・欠落除去の 6 command を用意し、入力 ID をすべて検証してからサービスを呼ぶ(パスは受け取らない)
  - 削除は非同期 command にしてメインスレッドを塞がない。エラーは種別・項目・メッセージを持つ形で reject する
  - 完了時: 不正な ID が見つからない / 拒否で返り、正しい ID でサービス結果がそのまま返ることを command 単位のテストで確認できる
  - _Requirements: 3.1, 3.4, 3.5, 3.6, 3.7, 4.2_

- [ ] 8. 履歴画面 UI
- [ ] 8.1 (P) 表示整形と複数選択ロジックを作る
  - 撮影日時を `yyyy/MM/dd HH:mm:ss`、サイズを `幅 × 高さ` に整形する
  - クリック・Ctrl・Shift による複数選択と、除去された ID の選択解除を純粋関数で扱う
  - 完了時: 整形と選択操作の Vitest が通る
  - _Boundary: format, history-selection_

## Implementation Notes
- 1.1: `png` は `image` 0.25 が使う版に合わせて 0.18 系にした(design の 0.17 系から変更、二重依存を避けるため)。`windows` の機能(Gdi / FileSystem / DataExchange / Memory / Ole)は app-shell と同じ依存行に capture-library 区画として追記した。asset プロトコルはスコープ空で有効化し、CSP の `img-src` は app-shell の雛形で既に asset を許可済み。
- 1.2: `CaptureId` は読み込み(serde)でも形式を検証する(`try_from`)。`_NN` は 02〜99 のみ受け付ける。
- 1.3: `LibraryError` の JSON は `{ kind, id?, path?, message }` で、`message` は利用者向けの日本語文(Display)。`DeleteOutcome.failed` は design のタプルではなく `{ id, error }` の構造体にした(IPC の形は design どおり)。
- 1.4: イベントは `LibraryEvent` 列挙と `emit` で発行する。サービスからは差し替え可能な発行関数として使う想定。
- 2.1: DIBV5 ヘッダと画素列への変換と PNG 化は OS に依存しない `platform::image_formats` に置き、Linux でも単体テストする。`ClipboardImage` もここで定義し、`platform::windows::clipboard` から再公開する(capture-library の `DesktopOps` が Windows 以外でもビルドできるように)。ペイント / チャットアプリへの貼り付けは手動 E2E(10.3)で確認する。
- 2.2: `reveal` は opener プラグインの `reveal_item_in_dir` 関数を直接呼ぶ(`AppHandle` 不要)。ごみ箱からの復元とエクスプローラーの選択表示は手動 E2E(10.3)で確認する。隠し属性は Windows CI の単体テストで確認する。
- 2.3: 本番実装 `SystemDesktop` は Windows 以外ではエラーを返す(Snipt は Windows 専用。テストは偽実装 `ports::fake::RecordingDesktop` を使う)。クリップボード使用中は「ほかのアプリがクリップボードを使用中です」の clipboard エラーにする。
- 開発メモ: Linux 上でも `cargo clippy --target x86_64-pc-windows-msvc --all-targets` で Windows 用コードの型検査ができる(リンクはしない)。
- 3.1: `naming::next_name` は 99 件まで埋まっていると `None` を返す(サービスで保存失敗にする)。ファイル名から元画像 / 合成済み画像と ID を判定する `naming::classify` も用意した(4.2 の突き合わせと 6.1 の監視で使う)。
- 3.2: `.snipt` の隠し属性の付与に失敗しても保存は続け、ログだけ残す。作成できない保存先は `saveDirUnavailable`(権限なし・容量不足はそれぞれの種別)にする。
- 3.3: PNG 入力は再エンコードせずチャンク列を書き換える(既存の `snipt:meta` を外し、IHDR の直後に非圧縮 iTXt を入れる)。チャンクの CRC を確かめ、壊れた / 途中で切れた PNG は入力不正にする。CRC 計算のため `crc32fast` を直接の依存に加えた(png が既に使っているもの)。
- 3.4: 容量不足は `ErrorKind::StorageFull` と Windows のエラーコード 112 / 39 で判定する。権限なしのテストは、Windows では読み取り専用ファイルの置き換え、Unix では書き込み不可フォルダで行う(root では権限が無視されるため、その場合は書き込めることを確認する)。
- 4.1: 索引ファイルの各項目は `base`(`Snipt_<id>`)を持つが、パスは ID から導出し、`base` が ID と一致しない項目は捨ててファイルから読み直す(パストラバーサル防止)。`thumbnailVersion` 0 はサムネイル無しを表す。並び順は撮影日時(時刻としての比較)の降順、同値は ID 降順。
- 4.2: `LibraryIndex::load` は名前の一覧(ルート・注釈・サムネイル)と索引を突き合わせ、何か変わったときだけ索引ファイルを書き直す(書けなくてもログのみ)。メタの無い `Snipt_*.png` は取り込まない。読み込み件数・取り込み・除外・補正の件数と所要時間を info ログに出す。
- 4.3: 縮小は `image::imageops::thumbnail`(面積平均、拡大はしない)。キューは ID ごとに合流し、撮影日時の新しい順に取り出す純粋な `ThumbnailQueue` に分け、スレッド無しでテストする。完了コールバックには新しい `thumbnail_version`(ミリ秒)か失敗理由を渡す。削除・保存先切り替え用に保留中の要求を捨てる `retain` を用意した。
- 4.4: `UnsavedStore` は PNG バイトを `Arc` で持ち、列挙は ID 順で返す。
- 5.1: `CaptureLibrary::open(LibraryDeps)` が索引をバックグラウンドで読み込み、各操作は読み込み完了まで待つ。OS やアプリに依存する部分(デスクトップ操作・通知・イベント発行・編集画面起動口の解決)は `LibraryDeps` で受け取り、テストでは記録用の偽物を渡す。`setup` は保存先のサムネイルフォルダだけを asset スコープに許可する。
- 5.2: 画素の PNG エンコードはロックの外で仮 ID のメタ付きで行い、採番した ID が違うときだけメタのチャンクを書き換える。索引ファイルは 300ms 待って合流させてから書き出す(`flush_index` で即時書き出しも可)。サムネイルは保存直後のメモリ上の画素から作る。
- 5.3: 入力不正は呼び出し側の不具合として error ログと通知にとどめ、開発時アサートは入れていない(テストで入力不正の経路を確かめるため)。入力不正のときは保持する PNG が無いので、未保存保持には入れない。`SaveCaptureError.unsaved` は `Result` を小さく保つため `Box<CaptureItem>` にした(JSON の形は変わらない)。未保存の ID は、索引・編集中・削除済み・未保存の ID と重ならないように採番する。
- 5.5: 未保存項目の再保存は、ID を保ったまま現在の保存先に書く。同じ名前のファイルが既にあるときはエラーにする。
- 5.7: 削除は `EditorLauncher` を呼び出し時に managed state から解決する。トレイトは annotation-editor 1.2 の定義どおり `shared::EditorLauncher` に追加した。ごみ箱への移動が失敗したときは、元画像がまだ残っている項目を失敗として返し、一覧に残す。
- 5.8: 終了前フックは `before_exit` で、未保存項目を現在の保存先に書く。書けなかった項目を「撮影画像: <ID>」として返す。
- 6.1: 監視は削除・リネーム系のイベントだけを集め、300ms 静かになったら ID にまとめて渡す。実際に消えたかはサービス側でファイルの有無を見て判断するため、重複や余分なイベントは無害。自アプリの削除では項目が既に索引から消えているので、二重に除去イベントは出ない。保存先がまだ無いときは監視せず、最初の保存の後で開始する。
- 6.2: 切り替えは `CaptureLibrary::switch_save_dir` で行う。設定の購読から別スレッドで呼び、そのときの最新の保存先に切り替える(連続で変更されても最後の値になる)。asset スコープは新しいサムネイルフォルダを許可するだけにして、旧フォルダの許可は外さない(Tauri のスコープは許可を取り消せず、forbid すると旧フォルダに戻したときに表示できなくなるため。サムネイルは利用者自身の画像の縮小版)。
